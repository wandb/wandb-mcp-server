## Summary

This candidate restores W&B username attribution in server analytics. Since
0.4.0 most events identified the actor only by an API-key pseudonym, which
analytics could not join to a user. At the `off` and `standard` privacy levels
the server now resolves the authenticated username once per actor and uses it
for session, request, and tool events.

## Highlights

- HTTP authentication resolves the W&B username with one viewer lookup per
  actor and endpoint, cached in process for six hours; STDIO reuses the viewer
  fetched by startup key validation.
- Lookups are bounded: at most four run concurrently on a dedicated executor, a
  request waits at most three seconds, failed lookups are cached separately for
  five minutes, and lookup clients never enter the functional client cache.
- `strict` privacy and `MCP_ANALYTICS_DISABLED=true` never perform the lookup.
- No tool, schema, or configuration surface changed.

## Security and privacy

Username lookups are telemetry-only and never used for authorization. Because
HTTP authentication validates key format only, well-formed invalid keys reach
the lookup; their failures are cached in a separately bounded table so they
cannot evict resolved users or their cached clients, and concurrency is capped.
Only exception class names are logged. `strict` remains pseudonymous.

## Known limitations

- A username stays cached for up to six hours after its key is revoked.
- When all lookup slots are busy, a cold actor's request is attributed by
  pseudonym until a later request.
- Hosted, customer, and Dedicated channels are pending.
