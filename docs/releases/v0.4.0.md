# W&B MCP Server v0.4.0

**Status:** Release candidate

W&B MCP Server v0.4.0 focuses on predictable performance, accurate bounded
analysis, safer W&B access, and clearer deployment behavior.

Production availability for the managed service and the Dedicated/Self-Managed
chart will be announced only after their separately versioned artifacts have
completed staging validation.

## Highlights

### SDK-first W&B queries

`query_wandb_tool` now reads projects, runs, sweeps, and reports through the
public W&B SDK. The default server does not expose caller-supplied raw GraphQL.

Run collections return core metadata by default. Callers can request:

- `summary_keys` for specific summary metrics.
- `config_keys` for specific configuration values.
- Full `summary`, `config`, `system_metrics`, or related details for bounded
  result sets.
- `response_mode="count"` for an exact server-side run count.

Individual run lookups still support complete run details. Collection-wide full
detail is intentionally limited because loading every field from many wide runs
can degrade the W&B application for other users.

### Explicit scope and accuracy

Collection, history, artifact, registry, schema, and evaluation tools now stop
at their configured bounds and report coverage explicitly. Depending on the
tool, responses include fields such as:

- `total_count` and `returned_count`
- `has_more`
- `project_exhaustive`
- `sampled`
- `truncated`

History reads support bounded range scans, custom axes, and target-value
verification. Analysis tools use selective server-side fields instead of
materializing complete run objects whenever the W&B API supports projection.

### Evaluation prediction reconciliation

`summarize_evaluation_tool` now counts only direct
`Evaluation.predict_and_score` children of each `Evaluation.evaluate` root.
Bookkeeping and summary siblings, along with nested prediction-like calls, are
excluded so prediction totals, coverage, and bounded detail aggregates describe
the same evaluation rows.

The Python package also constrains the MCP SDK to the compatible 1.x API. MCP
SDK 2.x removes the `mcp.server.fastmcp` module used by this release.

STDIO deployments now force analytics and startup logs to stderr, including
when `MCP_ANALYTICS_LOG_STREAM=stdout` is set. Standard output remains reserved
exclusively for MCP JSON-RPC messages.

### Workload protection

Hosted deployments use weighted admission control at the public tool boundary:

- Light calls cost 1 unit.
- Collection and history calls generally cost 2 units.
- Broad analysis, full-detail, and raw GraphQL calls cost 4 units.

Calls wait for capacity for up to two seconds by default. If capacity remains
unavailable, the server returns:

```json
{
  "error": "server_busy",
  "retryable": true,
  "retry_after_ms": 1000
}
```

This is a controlled overload response, not a W&B data error. Clients should
wait for `retry_after_ms` and retry rather than starting additional concurrent
calls.

Default workload profiles:

| Profile | Collection rows | History samples | Metric keys | Range rows | Full-detail rows | Actor/process units |
|---|---:|---:|---:|---:|---:|---:|
| `shared` | 100 | 500 | 20 | 5,000 | 3 | 4 / 16 |
| `dedicated` | 250 | 1,500 | 50 | 20,000 | 10 | 8 / 16 |
| `local` | 1,000 | 5,000 | 100 | 100,000 | 25 | admission disabled |

The default tool deadline is 30 seconds and the default W&B SDK request timeout
is 20 seconds. Operators can tune individual `MCP_MAX_*`, timeout, and admission
settings, but should change them only with representative load testing.

### Dedicated and Self-Managed routing

Dedicated installations can keep client access and user-facing links on the
public instance URL while sending backend MCP-to-W&B calls over the
namespace-local Kubernetes service:

```bash
WANDB_BASE_URL=https://customer.wandb.io
WANDB_INTERNAL_BASE_URL=http://wandb-api:8081
MCP_WORKLOAD_PROFILE=dedicated
MCP_ADMISSION_CONTROL_ENABLED=true
```

API-key validation, W&B SDK clients, report creation, analysis logging, run
history, and the optional raw-query transport use the resolved internal URL.
The server does not silently retry through the public ingress if an explicitly
configured internal URL fails.

Public project, run, sweep, and report links continue to use
`WANDB_BASE_URL`; internal service names are not returned to clients.

### Safer query and write boundaries

Raw GraphQL is available only when an administrator sets:

```bash
WANDB_MCP_ENABLE_RAW_GRAPHQL=true
```

That setting registers the separate `query_wandb_graphql_tool`. It accepts only
GraphQL queries; mutations, subscriptions, and mixed documents are rejected
before a W&B request.

For deployments that must expose no MCP write tools:

```bash
WANDB_MCP_READ_ONLY=true
```

This omits `create_wandb_report_tool` and `log_analysis_to_wandb`. It is
independent of the raw-GraphQL flag.

### Telemetry quality and privacy

Telemetry now:

- Attributes supported clients such as Codex, Claude Code, Claude Desktop, and
  Cursor separately from their vendor.
- Emits one event at the public MCP boundary for each tool invocation.
- Records the exact MCP method and public tool name.
- Uses a pseudonymous API-key-derived actor identifier.
- Excludes API keys, raw tool arguments, prompts, queries, filters, report
  content, and customer resource identifiers.
- Bounds dimensions and serialized event size.

Successful HTTP request telemetry is sampled for operational cost control.
Session and public tool events are not sampled.

### Security and CI hardening

The release updates security-sensitive dependencies, including MCP, GitPython,
and the development/test dependency set. The reproducible release lock includes
W&B 0.28.0 and W&B Workspaces 0.4.4.

CI now:

- Pins third-party GitHub Actions and the uv tool version.
- Scans locked dependencies with Grype.
- Scans Python source with Bandit.
- Retains the Grype report as a workflow artifact.
- Runs Socket Security, Python 3.11/3.12 tests, W&B-latest compatibility, and
  fresh-wheel construction checks.

## Breaking change

v0.3.x callers that passed a GraphQL document to `query_wandb_tool` must migrate
to the structured interface:

```text
query_wandb_tool(
  entity_name,
  project_name,
  resource,
  run_id?,
  sweep_id?,
  report_name?,
  filters?,
  order?,
  limit?,
  include?,
  summary_keys?,
  config_keys?,
  response_mode?
)
```

Use the existing specialized tools for entity/project discovery, run history,
artifacts, registries, automations, and integrations. If a required response
shape has no SDK equivalent, an administrator may enable the query-only raw
GraphQL escape hatch and the caller must use `query_wandb_graphql_tool`.

## Operator settings

| Setting | Default | Purpose |
|---|---|---|
| `MCP_WORKLOAD_PROFILE` | `shared` when hosted, otherwise `local` | Select bounded deployment defaults |
| `MCP_ADMISSION_CONTROL_ENABLED` | Enabled except for `local` | Enforce weighted actor/process capacity |
| `MCP_ADMISSION_WAIT_MS` | `2000` | Queue budget before `server_busy` |
| `MCP_TOOL_TIMEOUT_SECONDS` | `30` | Public tool deadline |
| `MCP_WANDB_REQUEST_TIMEOUT_SECONDS` | `20` | W&B SDK request timeout |
| `WANDB_INTERNAL_BASE_URL` | Unset | Server-side W&B API URL |
| `WANDB_MCP_ENABLE_RAW_GRAPHQL` | `false` | Register the query-only raw tool |
| `WANDB_MCP_READ_ONLY` | `false` | Omit the two write tools |
| `WANDB_MCP_ENABLE_WEAVE_AGENT_TOOLS` | `false` | Register Weave Agent tools |

See the [README](../../README.md#command-line-reference) for the complete
configuration reference.

## Validation

The release candidate is validated through:

- Ruff check and format verification.
- Full non-integration tests on Python 3.11 and 3.12.
- W&B-latest compatibility tests.
- Bandit, Grype, and Socket Security.
- Source distribution and wheel builds.
- Fresh-wheel import and server-construction smoke tests with raw GraphQL both
  disabled and enabled.
- Installed-wheel STDIO sessions using the official MCP client with MCP 1.28.1
  and 1.29.0, including Codex, Claude Code, and Cursor client identities.

Managed staging and Helm artifact validation remain separate release gates.
