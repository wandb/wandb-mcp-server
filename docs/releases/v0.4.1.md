## Summary

This note covers the merged public v0.4.1 source and the separately published
v0.4.1.1 customer image. The image-only revision does not create a new public
source version: it binds the v0.4.1 runtime to the customer packaging that
repairs the upgrade path from v0.3 charts. The release image translates
the old boolean tool selectors before starting the strict v0.4 runtime, so a
higher-priority legacy chart pin cannot make the new pod crash solely because
it rendered the former environment names. It also restores the established
Segment/Hex client categories and authenticated-user continuity that existing
0.3 dashboards consume.

## Compatibility

- The public MCP tools, schemas, protocol support, workload policies, and
  profile manifests are unchanged from v0.4.0.
- Dedicated compatibility accepts strictly parsed legacy booleans only in the
  reviewed customer image. It maps classic Weave and read-only selections to
  the equivalent typed selectors, then removes the legacy variables before the
  Python runtime starts.
- Unsupported Dedicated capabilities such as Agent tools, ARIA, and the extra
  raw-GraphQL tool remain unavailable. Enabling one through an old flag fails
  startup rather than broadening the customer tool surface.
- Conflicting old and typed settings fail with a bounded configuration error.
- Segment keeps the established `mcp_server.tool_call` contract: `tool_name`
  and `success` remain stable, and `mcp_client_app` retains its v0.3 categories
  while `agent_harness` carries the newer canonical taxonomy.
- At privacy `off`/`standard`, Segment again uses the validated authenticated
  W&B username as `userId`, with a key pseudonym fallback. `strict` remains
  pseudonymous, and direct/replayed events cannot inject a trusted username.

## Operator changes

Roll out this patch image through the normal User Spec release path while
leaving the existing Operator chart in place. The image accepts the legacy
selectors emitted by that chart, verifies any matching typed selectors, and
then starts the strict v0.4 runtime. Operators do not need to edit live custom
resources or remove image pins by hand.

Treat the later chart migration as a separate rollout. During the transition,
the selected chart must preserve settings understood by the previous image or
be applied only after this compatibility image is effective. Managed Spec owns
the chart and shared configuration; it does not own the MCP image pin.

## Security and privacy

The bridge does not add tools, credentials, permissions, endpoints, or
low-level workload overrides. Boolean values are parsed from a fixed allowlist;
error messages name configuration fields but never include their values.

The runtime now requires AnyIO 4.14.2 or newer. The release lock selects the
current compatible version rather than retaining the vulnerable 4.10.0 lock.

Viewer attribution is cache-only. Telemetry reads a validated username only
after functional work has already materialized the SDK viewer; it never creates
a client, fetches a viewer, or changes authorization. Raw tool arguments remain
excluded from every sink, and this change adds no Datadog identity fields or
hashes.

## Known limitations

- Username continuity is opportunistic: tool paths that have already
  materialized the authenticated SDK viewer use the historical username, while
  cold session/initialize events, Weave-only calls, and other viewer-free paths
  retain the key pseudonym. The runtime does not add a W&B lookup for analytics.
- Agent, ARIA, and extra raw-GraphQL tool flags have no Dedicated mapping.
- Legacy chart structures outside the reviewed environment-selector bridge
  remain on their existing chart until a separately reviewed migration.
- Direct telemetry forwarding, pod-held telemetry credentials, opaque
  `envFrom`, and release-critical numeric overrides remain unsupported.
- Publishing the customer image does not establish that an installation has
  upgraded successfully; configuration, health, functional behavior, and
  rollback still require target-specific verification.
