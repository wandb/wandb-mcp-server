## Summary

This candidate hardens ARIA turn polling, progress reporting, automatic root
thread titling, and bounded snapshot compaction when the optional `aria`
extension is enabled. No deployment channel is available yet.

## Changes

- ARIA bounded polling (`wait_seconds` up to 30) uses stepped intervals
  (`1s`, `2s`, `3s` cap) to reduce full-turn upstream polling bandwidth. When a
  turn snapshot has already been confirmed in the current call and a later poll
  attempt hits a transient `429`, `5xx`, timeout, or network error, the tool
  returns the confirmed progress with `poll_after_seconds` and sanitized
  `progress.poll_interrupted` metadata instead of failing the call.
- ARIA progress resolves tool names on `response` records from matching
  `invocation` `call_id` entries, surfaces `created_at` and bounded
  `elapsed_seconds`, and clarifies long-turn polling behavior in tool
  descriptions so callers keep polling a single active turn rather than inserting
  client-side sleep calls or starting duplicate threads.
- `aria_send_message` supports omitting `title` on root turns, calling the ARIA
  thread title generator and falling back to a bounded single-line prompt prefix
  while continuing to reject explicit blank or oversized titles before contacting
  the service.
- Oversized `include_turn=true` results compact the turn snapshot to core
  metadata plus bounded tail slices of `messages` and `tool_calls` before
  falling back to stub omission when required by the configured token budget.

This release retains the tool-profile, extension, and session behavior from
[v0.4.5](v0.4.5.md).

## Compatibility

Python 3.11 and 3.12 and the MCP/W&B SDK ranges remain unchanged from v0.4.5.
Tool names and profile selections remain unchanged. Omitting `title` on root
`aria_send_message` calls is backward-compatible with callers that supply an
explicit `title`.

## Breaking changes and migration

None. Existing callers passing explicit `title` strings on root
`aria_send_message` calls and polling `aria_get_turn` retain compatible request
and response shapes.
