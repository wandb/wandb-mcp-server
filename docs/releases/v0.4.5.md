## Summary

This candidate bounds Secret Manager calls and supports explicit secret
versions for session signing and Datadog forwarding. Session initialization
failures have sanitized error categories and a five-second retry cooldown.
The hosted HTTP wrapper also adds an explicit sessionless option that keeps
per-request Bearer authentication without requiring a session-signing secret.
No deployment channel is available yet.

## Compatibility

Python 3.11 and 3.12 and the MCP/W&B SDK ranges remain unchanged from v0.4.4.
Tool schemas and profile selections remain unchanged.

## Breaking changes and migration

Existing secret configuration defaults are preserved. Operators can pin the
new secret ID/version settings described in [Secret resolution](../secret-resolution.md).
Rotating the session signing key requires clients to reconnect.

The hosted wrapper can select `MCP_SESSION_MODE=stateless` to omit application
sessions. It authenticates each request with the caller's W&B credential, does
not issue session IDs, and ignores old session headers. Request and tool
telemetry remain available; session counts and retained client metadata do not.
Authenticated session deletion and idle GET streams return HTTP 405 in this
mode. It does not provide resumable streams or cross-request session state.

`MCP_SESSION_MODE=managed` is the wrapper's compatibility default. Sessionless
operation is an explicit deployment choice, never an automatic fallback when a
signing key fails. Moving back to managed sessions requires a qualified new
revision with an approved key; clients may reconnect. This option requires the
corresponding hosted wrapper and does not change the public STDIO transport or
automatically change Dedicated/Self-Managed installations.

## Rollback

Public source fixes forward. Hosted rollback must restore the previous image
and compatible configuration while retaining an approved, usable signing key.
A revoked key must not be restored to make old sessions work.
For a sessionless deployment, preserve its image and explicit mode as the
rollback target until the managed-session revision is verified.
