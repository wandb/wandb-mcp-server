## Summary

This candidate replaces the fixed list of concatenated tool-profile names with
a base profile plus an additive, order-free set of extensions. Operators keep
selecting one of three base profiles with `WANDB_MCP_TOOL_PROFILE` and add
optional groups with the new `WANDB_MCP_TOOL_EXTENSIONS` selector. Every
previously documented profile name still resolves to exactly the same tool set,
so existing deployments need no configuration change.

With this model the W&B-hosted shared workload can enable ARIA alongside Agent
Lens without introducing another profile name, and future groups no longer
require a new profile, a new hand-maintained tool count, or a chart allowlist
entry per combination.

## Highlights

- New `WANDB_MCP_TOOL_EXTENSIONS` selector: a comma-separated, order-free set of
  extension groups (`agent-lens`, `aria`, `raw-graphql`) composed onto the base
  profile. Blank (the default) adds nothing.
- `WANDB_MCP_TOOL_PROFILE` now names a base profile (`models-only`,
  `models-weave`, `models-weave-agents`). The legacy names
  `models-weave-agents-aria`, `models-weave-graphql-compat`, and
  `models-weave-agents-agent-lens` remain valid aliases for the same selections.
- Each extension declares the base groups it requires and the managed workloads
  that allow it; selection fails closed on an unknown extension, a missing
  required group, a repeated entry, or a managed workload that any selected
  group does not allow.
- The `aria` extension is allowed on the W&B-hosted `shared` workload. Dedicated
  still rejects `agents`, `agent-lens`, and `aria`; `raw-graphql` stays local
  only.
- Release evidence, the exact-profile smoke, and the generated documentation now
  enumerate every valid base/extension combination (11 resolved profiles, 22
  profile/access-mode manifests) instead of a hand-kept table.
- Tool names, schemas, descriptions, and behavior are unchanged. The packaged
  runtime contract changes (new selector, group metadata, aliases), so its
  digest changes.

## Breaking changes and migration

- None for existing configurations: every previously documented profile name
  resolves to the same tools. New deployments should prefer the base profile
  plus `WANDB_MCP_TOOL_EXTENSIONS`.
- The runtime-contract digest changes; downstream release manifests that pin it
  must be rebound to this release.

## Compatibility

- Python 3.11 and 3.12, MCP SDK range unchanged from v0.4.3.
- Helm/Dedicated: a chart that passes `WANDB_MCP_TOOL_EXTENSIONS` is optional;
  charts that only set `WANDB_MCP_TOOL_PROFILE` keep working unchanged.

## Operator changes

- W&B-hosted shared deployments that want ARIA set
  `WANDB_MCP_TOOL_PROFILE=models-weave-agents`,
  `WANDB_MCP_TOOL_EXTENSIONS=agent-lens,aria`, and an approved
  `WB_AGENT_BASE_URL` in addition to `AGENT_LENS_BASE_URL`.
- Startup logs and release evidence record the resolved profile name (for
  example `models-weave-agents-agent-lens-aria`), the base profile, and the
  extension set.

## Security and privacy

- Extensions never widen a managed workload beyond what every selected group
  allows, and endpoint presence alone never enables a group.
- No change to credential handling, logging, or analytics.

## Known limitations

- Dedicated has no approved ARIA or Agent Lens entitlement boundary; both
  extensions are rejected there.
