## Summary

This candidate adds offline, stateless-compatible MCP Apps for CoreWeave Agent
Lens, Weave Agents, and ARIA (`ui://wandb/agent-lens-insights.html`,
`ui://wandb/agent-conversation.html`, and `ui://wandb/aria-agent.html`), raises
MT-SaaS (`shared`) and Dedicated (`dedicated`) workload defaults with bounded
operator overrides (`MCP_ALLOW_LIMIT_OVERRIDES=true`), ports ARIA production
query semantics and sandbox `network_access` permission continuations into the
tool layer, and consolidates seven narrow micro-tools into orthogonal MCP
primitives. No deployment channel is available yet.

## Changes

- **Interactive MCP Apps for Agent Lens, Weave Agents, and ARIA:**
  - **Agent Lens Insights Explorer (`agent-lens` extension):** Adds `render_agent_lens_insights_tool` and self-contained offline `ui://wandb/agent-lens-insights.html` (`@modelcontextprotocol/ext-apps` + `zod`, MIT-licensed) gathering coverage weeks, clustering status, failure and intent category/cluster breakdowns with impact metrics (`no_failure` filtered out, `failingTurnCount` computed cleanly), and optional failure attributions in one parallel call, with `24h` / `7d` / `30d` window presets, example-turn drilldown, embedded multi-turn conversation preview, `https://`-validated Forge deep links, and `failureClusterToMarkdown` `ui/update-model-context` sync.
  - **Conversation & Span Trajectory Inspector (`agents` group):** Attaches self-contained offline `ui://wandb/agent-conversation.html` in-place to `get_weave_agent_conversation_tool` and `get_weave_agent_trace_tool` (with optional `selected_failure` pinning), preserving exact `content[0].text` JSON output while providing `Thread` and `Spans` views, clickable inline span citations, evidence-span highlighting, `read-write`-gated human reactions/notes and Agent Lens tag assignment, and `ui/update-model-context` sync.
  - **Shared offline MCP App bundler & URL scheme hardening:** Factors shared `PostMessageTransport`, theme/font synchronization, `^https://` client-side link validation across all shipped MCP Apps, SHA-256 bundle integrity checks, and unified `THIRD_PARTY_NOTICES.txt` generation.
- **MT-SaaS, Dedicated, and customer-configurable limits:**
  - Raises `shared` and `dedicated` defaults for request/tool timeouts (`60s` / `90s`–`120s`), full-detail runs, trace limits, history sample/key/step caps, GraphQL page size (`200`), capacity classes (`small` `8/8`, `medium` `12/16`, `large` `16/32`), and Dedicated HTTP burst rates (`300/min` per key, `2,000/min` global).
  - Enables `agents` on `dedicated` where `WF_TRACE_SERVER_URL` is configured, derives `<WANDB_BASE_URL>/traces` in `local` mode for custom Dedicated hosts so credentials never default to `https://trace.wandb.ai`, and wires `TraceService`, `agents`, and `agent-lens` HTTP timeouts to `MCP_WANDB_REQUEST_TIMEOUT_SECONDS` bounded by the active tool deadline.
  - Adds `MCP_ALLOW_LIMIT_OVERRIDES=true` (plus `MCP_HTTP_RATE_PER_KEY_PER_MINUTE` and `MCP_HTTP_RATE_GLOBAL_PER_MINUTE`) so Dedicated and MT-SaaS operators can tune workload and capacity limits within hard parser safety bounds while keeping `shared` session-security limits locked.
- **ARIA skill query semantics & sandbox permission continuations:**
  - `query_wandb_entity_projects` uses a bounded server-ordered `Entity.projects` GraphQL projection (`order="-updated_at"` default, returning `run_count` in one round-trip).
  - `probe_project_tool` adds `include_traces=True` to probe Classic Weave Calls and OTel Weave Agents planes alongside W&B Models runs (`telemetry_planes`).
  - `query_weave_traces_tool` / `count_weave_traces_tool` support `has_error=True` (`summary.weave.status IN ("error", "descendant_error") OR exception != None`) and list `status` filters; `summarize_evaluation_tool` extracts root `Evaluation.evaluate` `output` scorer summaries and counts `descendant_error` child rows.
  - `list_artifact_versions_tool` auto-resolves `type_name` from the project artifact inventory when `source="project"` and `type_name` is omitted; `list_wandb_automations_tool` adds `project`, `registry_name` (`wandb-registry-<name>`), `organization`, and `include_integrations=True`.
  - `get_agent_lens_category_breakdowns_tool` and `list_agent_lens_category_example_turns_tool` auto-resolve `window_days` (`7d` default) anchored to `latest_week` when `start_at`/`end_at` are omitted, attaching `coverage`, `clustering_status`, `empty_diagnostics`, and optional `include_volume=True`; `list_agent_lens_tags_tool` adds `include_distribution=True`; `list_weave_agents_tool` normalizes common `sort_by` aliases and adds `include_versions=True`; `get_agent_lens_guidelines_tool` removes the hidden `summarize_conversation_id` POST side effect.
  - `aria_send_message` and `aria_get_turn` handle ARIA sandbox `permission_requests` (`network_access`) and `agent_questions` without dropping `/workspace` state via SSRF-validated `allowed_network_domains`, `network_access_mode` (`prompt` default with MCP `ctx.elicit`, `auto_safe`, `auto_public`, `deny`, or `MCP_ARIA_NETWORK_ACCESS_MODE`), and `progress.phase` (`awaiting_permission` / `awaiting_user_input`).

## Compatibility

Python 3.11 and 3.12 and the MCP/W&B SDK ranges remain compatible with v0.4.6.
`get_weave_agent_conversation_tool` and `get_weave_agent_trace_tool` preserve
their exact text output while adding `structuredContent` and UI resource
metadata for MCP Apps hosts; write actions remain hidden and rejected when
`WANDB_MCP_ACCESS_MODE=read-only`.

## Breaking changes and migration

Seven narrow or zero-call tools were consolidated into their primary domain primitives:

| Removed tool | Replacement |
|---|---|
| `list_wandb_integrations_tool` | `list_wandb_automations_tool(include_integrations=True, integration_kind=...)` |
| `resolve_trace_roots_tool` | `query_weave_traces_tool(filters={"trace_ids": [...], "trace_roots_only": True})` |
| `list_weave_agent_versions_tool` | `list_weave_agents_tool(agent_name=..., include_versions=True)` |
| `get_agent_lens_insights_coverage_tool` | `get_agent_lens_category_breakdowns_tool(include_status=True)` (included automatically when `start_at`/`end_at` are omitted) |
| `get_agent_lens_clustering_status_tool` | `get_agent_lens_category_breakdowns_tool(include_status=True)` |
| `list_agent_lens_clusters_tool` | `get_agent_lens_category_breakdowns_tool(top_n_clusters=..., include_volume=True)` |
| `get_agent_lens_tag_distribution_tool` | `list_agent_lens_tags_tool(include_distribution=True, window_days=7)` |
| `get_agent_lens_guidelines_tool(summarize_conversation_id=...)` | Read full conversation turns via `get_weave_agent_conversation_tool` |
